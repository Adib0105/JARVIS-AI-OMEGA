## Windows setup

1. Install the CI-tested installer from the new change's **JARVIS-Windows-Setup** artifact after all checks pass. Preserve your existing profile/data.
2. Sign in or create a local Login ID/password. Use **Account / Subscription → Local profile** to change your name. There is no shared/default password.
3. In **Background / Weather**, download/select the local Vosk model, select your city, then choose **Enable always-on mode**. Windows microphone permission must be enabled.
4. Leave **Bring the window forward** off. Close the app into the tray and use Chrome normally. The PC must stay awake.
5. Say **Wake up Jarvis**, wait for the greeting/optional weather, then speak your command. Disable weather-on-wake when you prefer a shorter greeting. **Exit completely** stops the microphone.

Example structure: “Hello Adib, kaise hain? Main sun rahi hoon. … temperature … cloud cover … rain chance … US AQI …”. Values come from provider data. The name comes from the active local profile. Unknown readings are stated as unavailable. Forecasts are estimates; rain is never promised as certain. Air data is a CAMS model estimate, and the US AQI is not silently called Indian AQI.

Fast acknowledgement uses an installed Windows voice. Hindi pronunciation depends on installed speech voices. You can turn off Fast wake greeting to use the configured neural voice, which requires connectivity. Weather is prefetched only for a city you select and is refreshed while background mode is enabled. The first cold wake may say the weather is not ready; acknowledgement still proceeds.

## Online subscriptions

See [server setup](../server/README.md). The desktop can run without an account server. Online registration does not overwrite the separate local PC account. Online session tokens are held in memory and are never written into chat or .env; closing JARVIS ends the local session. The server expires them after seven days and supports logout/password rotation.

Existing local features are free. Paid service access is enforced by the backend for extended forecasts. This open-source desktop is not DRM: a user can modify their own local copy, but cannot self-grant access to the hosted paid endpoint.

## Verification and limits

- Desktop regression includes malformed weather/missing values, cache isolation, partial-wake deduplication, hot-model reuse, offline speech queue/STOP, personalized greeting, cached follow-up flow and local account isolation/session rotation.
- Service HTTP tests cover registration/login/logout, hashes, lockout, limits, password/session revocation, fixed payment destinations, server price/identity binding, duplicate/tampered/stale webhooks, out-of-order cancellation, expiry/delinquency and paid endpoint authorization.
- CI retains Linux 3.11–3.14, Windows 3.14, frozen desktop/speech, Defender, secret exclusion and install/update lifecycle gates. It now also tests the account service and opens the new subscription screen in the frozen desktop smoke.
- Automated checks cannot measure the user's actual microphone, audible latency, Windows sleep/privacy behavior, or real Chrome/tray/sign-in reliability. Run those on the target PC.
- Live merchant credentials, deployed HTTPS service, a real payment-provider test-mode checkout/renewal/cancellation cycle, licensed weather access, email verification/recovery and operational monitoring remain deployment work. No live charges were made.
- `FINAL-HARDENING-AUDIT.md` remains authoritative for unresolved production findings. Automatic public release publication remains blocked; a passing installer artifact is a test build, not a commercial-readiness certificate.
