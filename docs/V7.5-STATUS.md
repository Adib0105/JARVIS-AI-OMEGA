## Current release-candidate model

The source branch used for active engineering is `v7-development`. Historical V7/V7.5 filenames/labels do not define the current product version.

A green workflow is required for the exact commit being released. After any source, dependency, packaging or installer change, older CI/package evidence is no longer release evidence for the new commit.

## Windows automated gate

The workflow is designed to cover:

- Linux Python 3.11–3.14 regression;
- Windows Python 3.14.7 regression;
- constrained dependency resolution;
- compile checks and full tests;
- frozen EXE build;
- canonical PE version metadata verification;
- first-run/package/TTS-worker software healthchecks;
- release-bundle secret exclusion;
- Inno installer build and SHA-256;
- isolated installer install/uninstall without repository checkout/Python setup;
- shortcut/uninstaller validation;
- per-user data preservation;
- post-packaging full regression.

A workflow design is not itself evidence: the exact head run must complete successfully.

## Real workstation evidence still separate

Even with green CI, do not claim the following as verified until they are tested on the exact packaged candidate:

- audible TTS through a real speaker;
- physical microphone capture and speech recognition;
- real Chrome/Notepad UIA/keyboard/mouse behavior;
- OCR behavior on the actual screen;
- focus loss/wrong target/missing target behavior;
- DPI/resolution/window movement behavior;
- live provider inference with a real credential;
- practical timeout/rate-limit/unavailable-model recovery;
- disconnect/reconnect behavior;
- human-observed clean installed first run.

## Safety defaults

```env
SELF_DEVELOPMENT_ENABLED=true
PRODUCTION_SELF_MODIFICATION=false
REQUIRE_APPROVAL_FOR_PRODUCTION=true
AUTO_ROLLBACK_ENABLED=false
```

The controlled path remains:

```text
Discover → Propose → Sandbox → Build → Test → Security/Evaluation → Diff → Approval
→ Controlled Release → Post-test → Rollback if required
```

The audit chain is tamper-evident, not magic tamper-proof storage; operating-system/database access control remains part of the security boundary.

## Final status rule

Never convert automated software readiness into a claim of physical-device/live-provider verification. Missing external evidence stays `NOT VERIFIED`.
