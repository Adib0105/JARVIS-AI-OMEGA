# JARVIS OMEGA V7.5 — Premium Voice & Live Conversation

## What changed

V7.5 keeps the existing interruptible Edge neural TTS/pyttsx3 fallback and adds a voice-first response personality, speech-only cleanup, VAD endpointing, manual barge-in, and optional automatic live turn-taking.

The goal is a warm, calm, intelligent, conversational assistant experience. It does **not** clone, impersonate, or claim to reproduce any specific person or proprietary assistant voice.

## Pipeline

```text
Microphone
  -> local energy VAD / silence endpointing
  -> SpeechRecognition transcription
  -> JARVIS provider-neutral reasoning
  -> voice-first response formatting
  -> speech-only cleanup
  -> Edge neural TTS (pyttsx3 fallback)
  -> speaker
```

## Voice behavior

- English input -> natural English response.
- Hindi input -> natural Hindi response.
- Hinglish input -> natural Hinglish response.
- Short tasks prefer short conversational acknowledgements.
- Markdown, emoji, raw URLs, code blocks and long opaque identifiers are not read literally.
- Chat text is not destroyed or rewritten just to make TTS cleaner; speech gets its own cleaned copy.
- Default rate is near normal human conversation speed and can be changed from the Voice strip.

## Controls

- `MIC` / `Ctrl+M`: VAD push-to-talk. If JARVIS is speaking, this stops speech immediately and starts listening (deterministic manual barge-in).
- `LIVE: ON/OFF`: automatic turn-taking. When enabled, JARVIS listens after each spoken reply.
- `Esc`: stop current speech.
- `Ctrl+Space`: play/pause.
- `Ctrl+-` / `Ctrl++`: slower/faster.
- `Ctrl+Shift+V`: toggle Live mode.

## Configuration

```env
ENABLE_VOICE_OUTPUT=true
VOICE_ENGINE=edge
VOICE_HINDI=hi-IN-MadhurNeural
VOICE_HINGLISH=en-IN-PrabhatNeural
VOICE_ENGLISH=en-IN-PrabhatNeural
EDGE_VOICE_RATE=-2%
EDGE_VOICE_VOLUME=+5%
EDGE_VOICE_PITCH=-12Hz

ENABLE_MIC_INPUT=true
SPEECH_LANGUAGE=en-IN
VOICE_USE_VAD=true
VOICE_VAD_THRESHOLD=420
VOICE_SILENCE_SECONDS=0.75
VOICE_START_TIMEOUT_SECONDS=5
VOICE_MAX_UTTERANCE_SECONDS=15
ENABLE_LIVE_CONVERSATION=false
```

`ENABLE_LIVE_CONVERSATION` defaults to false because an automatically active microphone is a privacy-sensitive behavior. The user can explicitly turn it on from the visible Voice strip.

## Reliability behavior

- No microphone / denied device access: surfaced as a microphone error; desktop app remains running.
- Recognition miss: user gets a retry message instead of an application crash.
- Recognition service/network failure: surfaced as unavailable; text chat remains usable.
- TTS/Edge failure: existing offline pyttsx3 fallback is attempted.
- Empty transcription/response: ignored safely.
- Closing the app: active TTS playback is terminated by the existing voice shutdown path.
- Manual interruption: Ctrl+M/MIC stops current TTS before microphone capture.

## About full-duplex barge-in

V7.5 intentionally does not keep a permanently open microphone while the computer speakers are playing TTS. Reliable acoustic echo cancellation is device/driver dependent; without it, JARVIS can hear its own voice and falsely interrupt itself. The reliable current behavior is manual barge-in plus automatic listening immediately after speech. A future full-duplex mode should use an audio stack with acoustic echo cancellation and streaming STT/TTS.
