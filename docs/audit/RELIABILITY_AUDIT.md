# Reliability Audit — V8 Frontier Baseline

## Findings
| ID | Severity | Location | Problem | Root cause | Impact | Recommended fix | Status | Test required | Verification |
|---|---|---|---|---|---|---|---|---|---|
| REL-01 | P1 | voice capture | A native driver that ignores abort can keep microphone ownership; no separate native capture process exists. | Capture is bounded at Python/thread level but not isolated from a stuck native driver. | Wake/follow-up may require reconnect/restart. | Isolate capture in a supervised subprocess with heartbeat and restart policy. | PARTIAL | unplug/replug/Bluetooth/sleep tests | stalled process is killed/restarted without app freeze |
| REL-02 | P1 | mission/tool cancellation | Already-running synchronous side effects cannot always be safely preempted. | Python cancellation cannot undo external side effects. | Stop/cancel may arrive after action execution. | Add cancellable adapters where possible; otherwise checkpoint + reconcile + never blind-retry. | PARTIAL | cancellation fault tests | external state is reconciled before retry |
| REL-03 | P1 | durable background execution | No unified persistent mission daemon/task queue. | Desktop-centric lifecycle. | Long tasks do not meet requested restart-resume semantics. | Persistent queue + ownership lease + checkpoint + idempotency key per side effect. | OPEN | crash/restart E2E | task resumes once, no duplicate effects |
| REL-04 | P2 | updater | Binary rollback is improved but power-loss/disk-full/live-installer interruption remain physically untested. | Hosted CI cannot reproduce all host failure modes. | Update recovery may fail on real PCs. | Add target-PC fault matrix and journaled update phases. | PARTIAL | power/disk/kill tests | previous healthy install remains launchable |
| REL-05 | P2 | UI error handling | Command-center refresh contains broad `except Exception: pass` paths. | Defensive UI refresh favors availability. | Silent stale panels can hide degraded state. | Replace with redacted telemetry + visible degraded indicator; keep UI alive. | OPEN | injected refresh failures | error becomes observable without crashing UI |
| REL-06 | P2 | action replay | Durable intents reduce replay risk but exactly-once external execution is not guaranteed. | External systems may acknowledge ambiguously. | Duplicate form/email/payment/file action risk. | Reconciliation adapters + provider IDs + operation fingerprints + user-visible UNCERTAIN state. | PARTIAL | timeout-after-success tests | replay is blocked until reconciliation |
