## Verified existing controls

1. Self-debug retry count is bounded by `MAX_SELF_REPAIR_ATTEMPTS`, default 3.
2. Generated writes are restricted to a Git worktree sandbox and path traversal is rejected.
3. File-count and line-count limits exist.
4. Security core, rollback policy and environment/secret paths are protected from generated changes.
5. Self-improvement branches use `self-improvement/IMP-...` naming and Git operations are allowlisted.
6. Production deployment helper uses clean-worktree + expected-HEAD + fast-forward-only checks.
7. Rollback checkpoints persist known-good and deployed SHAs; rollback code avoids uncontrolled reset.
8. SQLite-backed leases and interrupted-state recovery exist in the engine.
9. CI already runs compileall and the full unittest discovery on Linux and Windows, with ResourceWarning promoted to error.

## Bugs / gaps discovered

### H-001 — benchmark evidence could be absent and still pass

`SelfDevelopmentEvaluator.compare()` previously treated no shared metrics as acceptable when tests/policy passed. This contradicted the requirement that insufficient evidence must not be called an improvement.

**Action:** fixed. Evaluation now fails closed when no comparable before/after metrics exist and requires at least one measured improvement with no measured regression.

### H-002 — benchmark helper allowed regression tests alone as improvement evidence

`SelfImprovementBenchmark.evidence_allows_success()` previously returned success when regression tests passed even without before/after benchmark proof.

**Action:** fixed. It now requires regression success, baseline evidence, candidate evidence, successful measured improvement, and zero benchmark regressions.

### H-003 — build and test timeout were conflated

The policy exposed `MAX_BUILD_TIME` but no independent `MAX_TEST_TIME` even though the hardening contract requires both.

**Action:** fixed at policy/config level with a bounded `MAX_TEST_TIME` default of 300 seconds. Engine wiring to the dedicated test timeout remains to be completed and tested.

### H-004 — engine review currently constructs empty evaluator snapshots

`SelfDevelopmentEngine.review()` calls the evaluator with empty before/after snapshots. After H-001 this must fail closed rather than incorrectly advance to approval. The engine must be wired to persisted benchmark evidence before the E2E lifecycle can pass.

**Status:** OPEN — next implementation target.

### H-005 — approval is not deployment

The current E2E test explicitly confirms approval only changes proposal state and does not merge production. A complete release/post-release verification lifecycle is therefore not yet proven by that test.

**Status:** OPEN.

### H-006 — sandbox resource limits need stronger verification

Path, file-count, line-count and process timeout controls exist. CPU/memory resource enforcement and cleanup behavior need deterministic tests, especially on Windows.

**Status:** OPEN.

### H-007 — failure-injection matrix not yet proven

The requested code-generation, syntax, unit/integration, debugger, benchmark, security, sandbox, Git, lease, interruption and restart failures require explicit deterministic scenarios and evidence.

**Status:** OPEN.

## Baseline status

The GitHub connector can inspect and modify repository files but does not execute the repository test suite locally. Therefore this audit does **not** claim baseline tests or CI are green. The configured CI is evidence of intended checks, not evidence of a successful current run.

Required executable baseline remains:

```text
python -m compileall -q .
python -m unittest discover -s tests -v
```

and all CI-equivalent checks.
